# Windows execution checklist

1. Detect Windows version, client version/path, selected source profile and enhancement hook, running core executable and uniquely accessible control pipe. Python 3.10+, PyYAML and Node must already work. The stock adapter requires the Clash Verge service and Meta TUN adapter; missing/nonstandard paths require agent adaptation before applying.
2. Discover exact node with client.py discover. Pass --subscription only when necessary. Never print server credentials or subscription URLs. Ensure exit requirements and authorization for strict firewall/browser restart are known.
3. Review candidate generation. `client.py prepare --node ...` captures a snapshot under `.local/snapshots/<timestamp>/` and writes sensitive candidates to .local. The first apply creates the snapshot automatically; later applies prefer the existing automatic baseline, falling back to the newest manual snapshot only if no automatic baseline exists. Use `-Action snapshot` only when the user explicitly asks for an extra restore point.
4. The entry snapshots system state and browser fields, seals backup hashes, then publishes persistent/client runtime changes. Full source node definitions and subscription providers are preserved. The renderer composes the prior enhancement script before the final secure override.
5. Apply browser/system settings and start a 180-second firewall rollback watchdog. A complete pass must set its commit marker; a failure attempts to restore original firewall settings while leaving a visible incomplete result for the full restore entry.
6. Verify standard traffic, qtypes 1/64/65, IPv6, node failure and core failure. Confirm routing from runtime connection metadata as well as HTTP statuses. Stock verify.py checks core selected group/config and connectivity; the agent must additionally observe the actual per-connection route when no sample was captured. HTTP 403 remains unresolved service usability, not a pass.

Automatic verification does not send HTTP requests to Claude/Anthropic. Use other foreign targets for outage testing and mark Claude transport/account usability untested. Git/npm attempts are bounded to 20 seconds with at most two attempts, use file-backed logs under `.local/tool-probes/`, and terminate the created Windows process tree on timeout. No credential prompts may open. Failed tested tools still fail the deployment.

Require four project outbound allows and one all-scope SharedAccess service block in both PersistentStore and ActiveStore. Validate effective policy immediately after applying and after network tests. A dynamic ICS allow may be treated as covered only when its actual system svchost path, SharedAccess service, NotRequired authentication and false OverrideBlockRules have been checked. Unknown dynamic/group-policy allows must fail even during supplement preflight. Keep virtualization and SharedAccess services running; document that the service block can affect connection sharing and virtual workloads, whose actual traffic remains unverified.
7. Validate Chrome and Edge in actual user profiles. Policy-only application may be ignored. Offline language preference edits require both browsers closed; preserve unrelated profile data. Default Intl locale is tied to supported UI resources and may remain zh-CN. Do not patch Chromium resources or inject JavaScript to fake it.
8. Record verified paths, firewall residuals, virtual networking and unsupported browser policy behavior. Do not call unrun Docker/WSL tests successful. Apply/restore may require a reboot; test again after adapter creation and OS/client updates.
9. Keep exactly one public entry at project root (`一键网络.cmd`, with an apply/restore menu). Agent helper scripts are internal dependencies. A fresh clone captures its own baseline on the first apply; there is no shared or inherited baseline.

Rollback: run the root restore entry. Never import another computer's .local state. If no privileged service exists or the control channel is ambiguous, stop before firewall mutation rather than fabricating a path. Restoring firewall defaults can change Internet availability; retain a local console and explain that before a remote-only deployment.

All-adapter IPv6 handling includes hidden, virtual and disconnected adapters. Record enabled bindings before mutation, recheck all adapters afterward, and restore baseline states plus journaled later adapters. Match exact GUIDs; never substitute a same-name replacement. Use binding instances for mutation. Normal restoration preserves originally disabled states and does not repair driver startup. Binding failures must produce an incomplete result.

Before closing applications, verify the firewall prerequisites or selected restore snapshot. When configuring browsers, also preflight user/machine ProxySettings, per-URL WebRTC overrides and machine Chrome ForcedLanguages; preserve conflicting policies and stop for review. Skip browser checks, closing and writes when `-SkipBrowser` is supplied. Restore only proxy fields in Git/npm/Docker files, preserving later unrelated settings. A pending watchdog rollback is pinned to its recorded snapshot and serialized with firewall writes; resolve it before a new operation. The 180-second timeout requests rollback after the current write step. Scheduled updates must skip unresolved guards or changed script associations.

A configured manual snapshot retains its pre-existing project scripts and their current rule updates. Remove only later project additions, preserving current subscriptions and user script choices. Missing required scripts or the exact selected node must stop preflight; do not revive old node-bearing runtime YAML. Validate regenerated configured runtime against current source nodes and routing invariants. Record verification stages under one operation ID, retaining node-outage/core-exit/recovery evidence separately. Failed tested STUN/git/npm checks fail verification; unavailable tools remain explicitly untested.
