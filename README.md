# Windows Claude 网络环境

Windows 11 + Clash Verge Rev / Mihomo 的本地网络配置工具：国内域名/IP 直连，Claude/Anthropic 优先固定代理，其余流量进入指定海外节点；节点故障不回落直连。

项目包含：

- 本地图形界面（GUI），覆盖配置、补充、恢复、快照、重新配置、规则更新和日志；
- 可审核的 Clash 配置生成器、恢复点和离线测试；
- 项目内运行环境（Python 3.13 + PyYAML + Node.js），不污染系统。

> 本项目不安装或登录 Claude，不处理账号，不保证账号可用性，不伪造浏览器指纹。仅支持 Windows。

**禁止连接 Claude 进行测试。** 开发、回归及验收不得访问真实 Claude/Anthropic 服务（包括 HTTP/API、WebSocket、相关域名 DNS），不得打开 Claude 网页、桌面程序或登录页，也不得为了测试启动浏览器。相关规则只用离线样例和 mock 验证，真实路由、应用与账号行为均标为未验证；此限制不影响用户另行授权的正常使用。

## 安装

详见 [INSTALL.md](INSTALL.md)。

1. 手动安装 **Clash Verge Rev** 及其内核，启动服务并导入订阅。本项目不会安装 Clash。
2. 双击根目录 **一键网络.cmd**。
3. 首次运行自动把 Python 3.13、PyYAML、Node.js 下载到 `.runtime/`；不修改系统 PATH，不安装到系统目录。
4. 界面打开后选择节点、确认影响并配置。


需要安装时，运行环境自动解析官方最新兼容版本：Python 选择 3.13 系列中提供 Windows x64 嵌入包的最新稳定版（跳过仅发布源码的版本），Node.js 选择提供 Windows x64 ZIP 的最新 LTS，PyYAML 按 `requirements.txt` 选择最新兼容版本。Python 从官方 Sigstore 记录读取 SHA256，Node.js 从官方 SHASUMS256.txt 读取 SHA256；缓存及新下载包均在解压前校验。缺少 pip 时下载 PyPA 官方当前 get-pip.py，记录内容 SHA256 并校验落盘文件，不再被旧脚本摘要锁住。官方元数据请求仅允许指定官方 HTTPS 主机且拒绝重定向；无法获取或校验失败时停止，不绕过校验。此信任基于官方 HTTPS，不声称独立验证了发布签名；PyPA 脚本无独立摘要来源。

已正常工作的环境继续复用，不在每次启动时强制联网或升级。安装中断后再次运行可修复缺失的 pip 和依赖，无需删除运行环境。实际下载来源、版本文件名及摘要保存在 `.local/runtime-downloads.json`。`assets/runtime-provenance.json` 保留历史审核参考，安装器不再用它锁定版本；`scripts/runtime_provenance.py --online` 仅核对该历史清单，不代表当前自动选择结果。

## 图形界面

根目录只有 **一键网络.cmd** 一个用户入口；`一键网络.cmd --menu` 是命令行备用入口。

| 页面 | 功能 |
|---|---|
| 一键配置 | 读取订阅和节点，自动填出口地区，确认后配置 |
| 网络环境 | 上次网络验收、检查与故障演练、维护与恢复 |
| 快照与恢复 | 保存快照、选择恢复点、查看配置关联 |
| 规则更新 | 手动/定时、更新间隔、立即更新、任务状态 |
| 日志与验证 | 上次操作、验收摘要、本地日志、重配置记录 |
| 使用说明 | 操作边界、故障处理、当前配置详情和浏览器状态 |

各操作页保留主要状态和按钮，补充说明通过圆形问号悬停或键盘聚焦查看。一键配置的完整变更对照位于节点选择下方，默认折叠；使用说明按主题展开，包含规则更新校验、恢复边界、当前配置和浏览器详情。快照页仅在设置保存中断时显示恢复入口；日志页默认收起已通过的验收明细，错误和待恢复事项直接提示。

界面服务只监听 `127.0.0.1` 的随机端口，使用一次性令牌、`SameSite=Strict` 会话 Cookie、CSRF 头、同源 `Origin` 和 CSP。界面以普通用户运行；配置/补充/恢复/快照/重配置在点击后请求管理员权限。

系统状态在后台读取，查询失败或结果过期时会显示提示与上次成功读取时间，不把缓存结果当作当前实测。自动刷新通过固定区域标识保留未保存表单和已打开日志；保存期间新增的编辑仍保留为待保存草稿。旧查询结果不会覆盖已保存的新状态。


## 配置内容

「一键配置」保留两种独立的配置方式：「单一节点配置」选择一个已有节点；「链式代理配置」选择前置、后置节点及新名称，也可选择已有链式配置。两种表单分别保留选择，可以先配置单一节点，再添加链式代理，也可以反向操作；已配置的另一种方式不会被删除。使用时选择相应配置，全局网络同一时刻使用当前选中的配置。

链式配置使用同一套安全生成器、系统防护、写入确认、两阶段看护、规则更新和恢复流程；不改写两个原订阅或原节点。普通与链式配置一起同步规则，出口地区按后置节点选择。配置不会自动运行网络验收，不能据此声称已验证真实防泄露或 Claude 可用性。

两跳节点以原订阅的精确参数生成独立本地配置，任一跳不可用均不回落直连。完整复核会分别演练前置和最终出口故障，再执行 TUN/停核与恢复阶段；首次基线保持不变。所有链式关联和节点候选仅保存在本机 `.local/` 及已安装的 Clash 配置中，不随安装包发布。

链式订阅卡片的流量条读取 Clash 已缓存的两份原订阅账户数据，按 `总量 − 上传 − 下载` 比较剩余流量，显示剩余量较少那份订阅的已用量/总量；不是分别取最小总量和最小已用量，也不是链式节点独占的累计流量。到期日取两份订阅中较早的有效日期；任一份流量缺失、无有效限额或数据无效时不显示流量条。同一订阅的两个节点显示共享账户额度，实际链式消耗可能重复计费；倍率、协议开销和其他设备用量会影响可用量，不能保证显示值等于可传输字节数。配置时写入，之后本软件规则更新时同步缓存数据；不额外请求订阅、不实时计费，先在 Clash 更新原订阅可取得较新的数据。Clash 已打开时可能需要重新打开客户端才能看到外部写入的流量条。

| 项目 | 行为 |
|---|---|
| 固定节点 | 创建只包含指定节点的 select 组，不含 DIRECT 或自动轮换 |
| Claude 优先 | 核心/补充域名、Claude 进程和官方入站 IP 先于国内规则 |
| 进程匹配 | 明确使用 Mihomo 的 `strict` 模式，避免继承关闭状态或 YAML 布尔值导致校验失败 |
| 海外域名优先 | geolocation-!cn 及对应 DNS 策略先于国内白名单走固定海外组 |
| 国内分流 | 已审核国内域名、国内 IP 与 GEOIP,CN 直连；IP 规则使用 no-resolve |
| 海外兜底 | MATCH 指向固定节点组，不回落 DIRECT |
| DNS | fake-IP；默认海外 DoH，国内名单使用国内 DoH；所有真实解析路径附加 Type 64/65 过滤 |
| TUN | mixed、auto-route、strict-route；接管 TCP/UDP 53 |
| IPv6 | Clash/DNS 关闭，系统全局关闭并关闭所有现有网卡 IPv6 绑定；需重启 |
| 代理清理 | 清理系统、WinHTTP、环境变量和 Git/npm/Docker 代理覆盖 |
| 严格防火墙 | 默认出站 Block，保留核心、TUN、LAN、DHCP 必要路径，阻断 SharedAccess 服务出站 |
| 系统自动定位 | 使用 Windows DisableLocation 策略关闭系统定位；恢复时还原原值（原无此项则删除），不强制开启原本关闭的定位 |
| 自动时区与自动时间 | 关闭自动时区服务及 Windows 自动校时（NoSync），保存服务启动方式、运行状态和原校时模式，恢复时逐项还原 |

严格防火墙下：节点故障但核心仍在运行时，国内网站保持直连；**核心停止时所有公网（包括国内）都会被阻断**。这是保护行为。

防火墙看门狗分别限制准备阶段和防火墙阶段：准备阶段最多 180 秒；首次修改防火墙前开始另一个 360 秒计时窗口，覆盖防火墙写入和本地写入确认。任一阶段超时都会请求回滚，等待当前互斥写入完成后执行。

## 出口地区自动识别

选择节点后，界面会从节点名和订阅名识别国家/地区并自动填入出口地区，例如 `demo-sg-01`、`🇸🇬 Singapore`、`US-01`、`demo-US`。识别只使用名称提示，不是实际探测；**实际出口可在配置后通过独立的连通性检查核对**。识别错误或无法识别时可以手动选择。




Windows「设置 → 时间和语言 → 语言和区域 → 区域格式」也随所选节点的出口地区配置，无需另行手动选择。例如 `bo-SG` 对应新加坡，区域格式为「中文（新加坡）」`zh-SG`；美国对应「英语（美国）」`en-US`。一键配置及补充配置同步处理此项，配置前的变更预览显示已保存的当前值与目标值。按节点名称识别的地区可手动修正，并非实时定位节点城市。恢复快照会还原首次记录的区域格式（例如「简体中文（中国大陆）」`zh-CN`），不覆盖原始基线。已保存格式与当前 Windows 会话的实际格式可能不同：设置窗口需重新打开，部分系统界面及应用可能需注销后重新登录或重启才生效；写入验证通过不代表已完成重启后的界面验收。

## 规则更新

本机登记的独立链式配置也会随项目规则更新同步：原订阅的增强脚本与链式配置一起备份、发布，失败一起恢复；当前启用链式配置时重载链式配置。源订阅关联或链式配置被手动修改时停止，不覆盖用户改动。节点参数从原订阅精确选取后内嵌到独立配置，兼容服务模式的隔离运行目录。前置节点有专用节点 DNS 时，仅对该节点的服务器域名保留原订阅的加密解析器，并附加 Type 64/65 过滤，不改变目标网站 DNS 分流。原订阅更新后，在本软件执行规则更新即可同步节点参数和节点 DNS；即使分流名单未变化，节点参数变化仍会发布。指定节点消失时不替换节点，空集合回退为 REJECT。此功能不自动创建联网验收，也不验证 Claude 服务、账号或浏览器行为。

配置及更新下载固定 GitHub 规则来源时，先直连，失败后尝试 Clash 当前配置中不带认证的本机 HTTP/mixed 端口（仅 `127.0.0.1`）。每条通道最多尝试两次，每次超时 15 秒；不读取系统代理或使用旧缓存，下载失败保留明确错误并停止。

四份规则来源并行下载，全部下载并校验后才保存候选摘要。网络验收中的六项 DNS 检查并行执行，Git、npm、UDP STUN 也并行执行；每项仍独立记录结果，失败仍阻止验收。系统设置写入、节点故障、TUN 关闭、停核和恢复按顺序执行，不同时启动多个配置任务。

在「规则更新」选择：

- **手动**：不注册后台任务；打开软件后点击「立即更新」。
- **定时**：注册当前用户的 Windows 计划任务。可设置：
  - 每天、每 3 天、每周、每月、每半年；
  - 或自定义 1–365 天的间隔；
  - 指定更新时间（HH:MM）。

定时任务只在当前用户登录期间运行。更新只刷新已审核的国内/私有来源，不更新内核或节点；来源变化过大、Claude 策略变化或脚本关联改变时会停止并保留旧配置。不下载或合并第三方 Claude 候选名单。

配置流程读取界面选择；恢复流程移除任务；界面可立即更新并显示上次结果和下次运行时间。

保存更新方式与配置、恢复等操作共用互斥保护，保存及恢复期间不能退出界面。修改前将原设置及计划任务的 XML、权限保存到 `.local/gui/settings-transactions/`，并持久化记录操作阶段及备份校验值；失败时一起恢复，原本不存在的文件或任务仍恢复为不存在。断电或进程中断后，重启界面会发现未完成的保存，暂停新的修改；在「快照与恢复 → 未完成的设置保存」点击「恢复原设置」后可继续。备份校验失败时不重放，恢复失败可重试。这些记录独立于网络快照，不改变首次基线或旧快照格式；没有阶段记录的旧版历史备份不会被猜测为中断操作并自动重放。

## 外部浏览器

本软件不再提供内置浏览器、指纹配置、环境检测页、语言同步或默认浏览器注册。请自行安装和管理浏览器。管理界面仍通过本机已有的 Edge/Chrome 显示，只允许打开本机管理地址。

配置和补充配置会管理标准 Chrome、Edge、Firefox 的 WebRTC 策略：Firefox 锁定 `media.peerconnection.enabled=false`；Chrome/Edge 设置 `disable_non_proxied_udp`，并自动设置各自官方商店的 WebRTC Control 强制安装策略，已有商店扩展直接复用；同时准备项目自带离线扩展作为备用。不修改默认浏览器资料，不启动浏览器，不管理外部指纹浏览器。

离线扩展完整文件存放在仓库的 `assets/webrtc-addon/`，随 Git 提交和安装包一起提供。新机器克隆或拉取最新项目即可取得，不需要从扩展商店另行下载。使用项目 MIT 许可，不是商店版 WebRTC Control。配置直接读取这些项目文件，先核对 `bundle.json` 内的文件摘要，再准备到 `.local/webrtc-addon/1.0.0`；后续配置直接复用，文件被改动时停止，避免覆盖用户修改。扩展无下载地址、远程代码、统计或账号功能。

一键配置自动安排从各自官方商店安装 WebRTC Control，无需手动添加。浏览器运行时自动执行，关闭时在下次正常启动后执行。Chrome ID 为 `fjkmabmdepjfammlpliljpnbhleegehm`，Edge ID 为 `eepeadgljpkkjpbfecfkijnnliikglpl`。

默认保持上述静默安装流程。配置结束时会再次读取标准资料的扩展安装记录；尚未完成时，完成提示列出浏览器并给出项目离线包的手动加载方法。正常重启浏览器后仍未安装，再使用离线备用方式；已安装扩展继续复用。网络验收通过不表示扩展已安装或实际运行效果已验证。

离线备用方式：普通非域管理 Windows 的 Chrome/Edge 不支持从本地文件静默安装进现有资料。需要使用备用包时，在 `chrome://extensions` 或 `edge://extensions` 启用开发者模式，点击“加载已解压的扩展”，选择「使用说明 → 常用浏览器 WebRTC」显示的目录；每份标准资料加载一次，后续直接复用。加载后刷新已有网页。不要删除或移动该目录。已有商店版及历史强制安装策略保持原状，避免自动卸载；浏览器会自动安装和更新商店版。Firefox 不需要扩展。

“网络保护”的当前状态与配置后使用相同口径，设置写入成功统一显示“已配置”。Chrome/Edge 策略和静默安装安排写入后即为已配置；扩展实际安装记录单独说明。“仅 1/3 份标准资料有安装记录”表示三份浏览器用户资料中检测到一份安装，并不表示当前使用的资料安装失败，也不表示另外两份已安装。Firefox 禁用策略齐全后显示“已配置”。网络验收结果独立展示，配置状态不代表扩展实际运行或网络已验收。

离线扩展通过 MAIN world 的 document_start 脚本阻止网页创建 RTCPeerConnection，并补充非代理 UDP 限制。隐私窗口须另行允许；浏览器内部页、受限页、扩展页及 Worker 等环境不保证覆盖，实际浏览器行为未验证。网页语音、视频及点对点连接可能受影响。

改动前记录 `webrtc-policies.json` 和 `webrtc-extensions.json` 并封存到关联快照；离线版恢复点升级时另外封存 `webrtc-auto-extensions.json`，保留原只读记录；旧基线只补存新增记录，不覆盖原系统基线。恢复还原受管策略及自动安装扩展条目，保留其他扩展条目后续变化；撤销旧强制安装条目可能触发浏览器卸载商店版。手动加载的离线扩展由用户在扩展页移除，本地目录保留。旧快照没有相关记录时保留当前设置。

## 快照与恢复

- 第一次配置前自动保存原始恢复点到 `.local/snapshots/<时间戳>/`，之后沿用同一个首次恢复点，不覆盖。
- 「保存当前快照」按当前状态新增一份，不覆盖旧快照。
- 快照以卡片展示保存时间、类型、配置关联及系统记录封存状态，选中后点击「恢复所选」。封存状态不代表已完成全部文件完整性校验，恢复前仍执行校验。
- 不再需要的快照可在卡片底部点击「删除」，确认后永久删除备份文件。首次恢复点、当前配置或恢复流程引用的快照禁止删除；操作进行中或关联记录异常时也会阻止删除。删除不更改当前系统设置。
- 恢复按时间倒序列出全部快照，选择要恢复的一份；保留当前订阅、节点更新、删除和用户后来选择的脚本。
- 恢复不运行网络验收；IPv6 和语言通常需要重启 Windows 才完全生效。
- 恢复会移除本项目的定时更新任务；需要时在「规则更新」重新保存。
- 配置、补充、恢复、快照和定时更新共用 `.local/operation.lock`，同一时间只执行一项。

定位原值单独保存在恢复点的 `location.json`，重复配置不覆盖。旧恢复点在首次使用新版配置/补充时补存定位改动前状态，不改写原始系统基线；没有定位记录的旧恢复点不更改定位并显示提示。定位策略可能需重启或重新打开应用后生效；IP 推断位置、浏览器和虚拟机实际行为未验证。

国家/自动时间新增恢复信息保存在恢复点的 `region-time.json`，并在改动前封存。包括原国家 GeoID、区域格式、时区、两个时间服务的启动方式/运行状态/延迟启动项以及自动校时模式；原本不存在的值在恢复时删除。旧恢复点仅补存以前未管理的项目，原有时区/区域格式仍采用首次系统记录，不覆盖基线。恢复不会把时钟拨回备份日期；自动校时原本开启则还原该配置，能否实际联网校时须实测。缺少新增记录的旧恢复点会提示并跳过新增项目；记录损坏或恢复校验失败会报告未完成，不报告成功。


## 恢复与故障处理

| 情况 | 处理 |
|---|---|
| 缺少 Python / Node | 重新运行 `一键网络.cmd`，自动安装到 `.runtime` |
| 取消管理员授权 | 不执行操作；重新点击并在 UAC 确认 |
| 节点不存在或重名 | 在「一键配置」重新选择；不会自动替换 |
| 预检失败 | 查看界面错误和 `.local/last-error.log`；通常无需恢复 |
| 候选配置校验失败 | 查看 `.local/client-error.log` 和 `.local/candidate-validation.stdout.log`、`.local/candidate-validation.stderr.log`；日志可能包含节点信息，仅供本地排查 |
| 写入后失败 | 在「快照与恢复」恢复关联快照 |
| 防火墙回滚失败 | 公网可能仍被阻断；在「快照与恢复」重试，见 `.local/rollback-error.log` |
| 网络验收失败 | 查看失败项；不使用上一次成功记录 |
| 规则更新失败/跳过 | 保留旧配置；查看「规则更新」或 `.local/update-result.json` |
| 双击后窗口关闭、未看到界面 | 启动器会确认本地服务和独立浏览器就绪；失败时保留错误窗口。查看 `.local/gui/startup.stderr.log` 和 `.local/gui/server.log` |
| 界面一直显示“操作进行中”，但控制台已关闭 | 若任务已有错误/完成事件，点击任务面板的「结束卡住任务」；仍不行时在任务管理器结束运行 `run.ps1` 的 `powershell.exe`，再重新打开界面 |

## 验证

一键配置只生成、校验并写入配置，确认本机内核加载、系统写入和回滚保护；不自动访问测试网站，不运行联网检查或节点/TUN/停核故障演练。成功表示本地配置完成，不表示网络验收通过。

在「网络环境 → 检查与故障演练」分别点击「检查连通性」或「完整复核与演练」。连通性检查不制造故障；完整演练会短暂中断公网。恢复并重新配置也不自动运行联网检查；独立恢复看护在紧急恢复时仍可检查基本联网。旧验收记录保留为历史，新配置不会沿用历史记录显示本次验收通过。

`scripts/verify.py` 检查：

- 国内网站 HTTP 200；
- 海外出口国家与所选地区一致；
- 出口查询最多尝试三次，连接失败或 HTTP 非 200 时等待 2 秒后重试，保留每次结果；持续失败仍停止验收；
- DNS A 有结果，64/65 为空；通用测试域名 `example.com` 得到 fake-IP（不探测 Claude 域名）；
- 公网 IPv6 不可达；
- UDP STUN 出口与节点路由；
- STUN 每个端点最多两次、每次 UDP 响应超时 5 秒；Google 端点失败后尝试 Cloudflare 公共 STUN（`stun.cloudflare.com:3478`），保存全部尝试。仍须取得有效公网映射、固定节点路由和正确出口地区，全部失败不会跳过验收；
- Git/npm 出口；
- 节点故障时海外阻断、国内保留；
- 节点恢复后的出口查询最多三次、间隔 2 秒，逐次保存 `recovery_attempts`；持续失败或出口地区不符仍停止验收，不把恢复配置请求成功当作网络已恢复；
- 核心停止时国内外公网都阻断，重启后恢复。

不测试或需人工确认：

- Claude 网页/账号可用性；不安装、不登录 Claude；
- Claude/Anthropic 真实域名 DNS、HTTP/API 及真实流量分流；禁止为测试访问；
- Docker/WSL/虚拟机内部出口；
- 任意应用自带加密 DNS。

国内域名统一使用 Loyalsoldier/clash-rules 的 direct.txt，国内 IP、私有域名、局域网地址分别使用 cncidr.txt、private.txt、lancidr.txt；不融合其他直连名单。保留精确域名与 +. 后缀的原始语义。首次切换来源请在规则更新页点击「立即更新」，定时任务会提示等待手动迁移。

更新先下载并严格校验四份来源，保存候选摘要；未发布前不覆盖已应用来源记录。国内域名/IP 的增删总量超过 max(100, 原数量的 10%)、私有/LAN 变化、新增过宽 IP 网段或未经审核的顶级域时停止。首次明确手动切换仅豁免国内域名的数量差异，其余保护仍生效。内容和生成版本均未变化时不重载。

每次发布前在 .local/rule-updates/ 保存更新前文件及校验摘要；发布后通过本机控制通道核对海外优先顺序和规则数量，失败尝试恢复。未完成事务在下次更新前先恢复；发现用户后续改动或备份校验失败则停止，不覆盖用户修改。来源记录和配置版本随成功发布一起更新，界面显示规则数量及增减；恢复失败明确标记待处理。规则更新不连接 Claude/Anthropic，不启动浏览器，不更新 geosite.dat/geoip.dat 或内核。

完整复核与故障演练：在「网络环境」点击对应操作，经 Windows 管理员授权后检查完整防火墙，再分别演练节点故障、关闭 TUN 但保持同一内核运行、内核退出，并在恢复后复测及再次复核防火墙。不重新配置规则、节点或系统地区，不启动浏览器，不访问 Claude/Anthropic。公网会短暂中断。

TUN 演练先确认正常状态可连接通用测试 IP，再启用独立本机恢复看护，只临时切换 TUN 开关；核对关闭状态、网卡状态及同一内核进程，验证新建直连 TCP、UDP/TCP DNS 被阻断，最后恢复 TUN。显式本机代理、浏览器及虚拟网络不在此演练范围内。恢复未完成时阻止后续项目操作并保留 .local/tun-drills/ 记录。

防火墙复核必须验证管理员权限、核心文件可读、实际运行路径、三个有效配置文件、PersistentStore/ActiveStore 中五条项目规则的全部筛选条件，以及其他有效放行规则。权限不足、核心不可读或证据不足不得标记完整复核通过。仅同一操作中包含节点故障、TUN 关闭、停核、恢复后复测、前后两次完整防火墙复核，才显示完整网络验收；旧三阶段报告显示部分阶段。

故障演练恢复后会重新关闭并核对所有网卡 IPv6 绑定，处理 Meta 网卡重建时自动启用绑定的情况；恢复失败会记录为本次验收失败。


## 软件打包与更新提示

软件更新入口位于顶部配置状态旁的小图标，不再作为独立页面。每次打开界面都会检查，只有确认发现新版时才显示下载图标及「发现新版本」，其余状态隐藏图标。点击弹出程序版本、GitHub 正式版本和最近检查时间；顶部「定时更新分流规则」明确区分规则更新。通过顶部图标也可手动再次检查；仓库可访问但尚无正式 Release 时记录「尚未发布正式版本」，不误报网络失败。只访问 assets/app-release.json 指定项目的 GitHub Releases；不带账号令牌、不继承系统代理，直连失败后仅尝试无认证本机 Clash HTTP 代理。失败、限流、仓库私有或没有可访问的发布时显示无法检查，不声称已是最新。软件只提示更新，不自动下载安装或覆盖程序。

在「使用说明 → 导出便携安装包」点击「生成 ZIP 安装包」后下载安装包，界面显示 SHA-256。包内只包含 assets/package-files.json 明确列出的程序、界面和文档，以及逐文件 SHA-256 清单；不包含 .local、.runtime、订阅、节点、密钥、快照、日志、Git 数据或其他未批准文件。包内唯一用户入口为「一键网络.cmd」，首次启动下载运行环境；新电脑首次配置创建自己的基线。

维护者可在项目内 Python 环境运行 `scripts/package_app.py`；输出位于 `.local/packages/<编号>/`，包含 ZIP 和同名 `.sha256`。发布前运行 `scripts/check_project.py`、检查包内容及差异，将 ZIP 和校验文件上传到 assets/app-release.json 指定仓库的正式 Release，并使用与版本文件一致的 `v主版本.次版本.修订号` 标签。打包不会提交、推送或发布到 GitHub。新增发布文件须更新明确文件清单。

更新已有安装：等待操作完成，点击「退出界面」，将正式 ZIP 内程序解压覆盖原目录，保留原 .local 与 .runtime，重新运行「一键网络.cmd」。不要将本机 .local 或运行环境复制到发布包；不要删除或替换原始基线。


## 配置性能与操作选择

完整配置先在 Clash 客户端仍运行时并行下载并严格校验四份分流来源，成功后才关闭客户端、重新读取当前订阅并生成候选。准备记录只在 `.local/rule-preparations/` 保存，属于本次操作、15 分钟内有效且只消费一次；损坏、过期或生成代码改变时停止，不回退旧缓存。写入前核对订阅索引、所选源文件、增强脚本、相关 LAN 缓存及运行配置的摘要，发现期间改动则停止，不覆盖外部修改。

YAML 读写优先使用项目已有的安全 C 实现，缺失时回退安全 Python 实现；不增加系统依赖。一次准备过程内复用订阅索引和已识别的内核路径，配置状态优先读取关联项目脚本，仍在每次查询时重新检查文件。

按变更范围选择操作：只刷新分流名单使用「规则更新」；新增网卡或可补充的系统设置偏差使用「补充配置」；切换精确节点、出口地区或生成版本不一致使用「一键配置」。完整恢复并重新配置保留为维护动作。网络环境页根据已读取的本地检查结果提供建议，过期或缺失结果不能证明无变化；建议不会自动执行或跳过本机确认、防火墙复核、首次基线和恢复保护。本地一致也不代表网络已验收。

每次配置的步骤、规则下载/解析、候选生成/校验及备份等耗时记录在 `.local/performance/`。步骤与 Python 阶段通过同一操作编号关联，使用单调时钟；嵌套阶段不能直接相加。记录只含固定阶段标识、动作、状态和耗时，不包含节点、订阅、配置正文、密钥或错误正文。记录失败不阻断配置或恢复。直接运行内部 Python 操作时使用独立记录；规则更新同样记录准备和发布时间。真实配置总耗时需在正常使用时测量，离线样例加速比不等于整次配置加速比。
