# Windows Claude 网络环境配置与恢复

本项目用于 Windows 11 + Clash Verge Rev / Mihomo：国内域名/IP 直连，Claude/Anthropic 优先固定代理，其余流量进入用户指定的唯一海外节点；节点故障不回落直连。它包含 AI 智能体 skill、可审核的配置生成器、详细说明及一个带配置/恢复菜单的一键入口。

**不安装 Claude、不处理账号、不承诺不封号、不伪造浏览器指纹。** 仅 Windows 适配器在支持范围内。默认要求出口为 SG；节点名、旗帜、ASN 或第三方评分不能代替实际出口验证，也不能证明账号符合服务地区政策。

## 在另一台 Windows 电脑复用

把私有仓库授权给你的 AI 智能体，然后发送：

> 阅读 https://github.com/bohaibo/clash-claude-network 中的 SKILL.md 和 README.md，根据其中流程配置这台 Windows 电脑。使用我已有订阅中的节点「填写完整节点名」，出口要求新加坡。保留全部原节点、订阅、局域网规则和浏览器数据。先发现实际配置并备份，生成候选再应用，完成验证，留下完整记录和一个带菜单的一键入口。遇到节点歧义或缺少必要依赖时向我确认，不要猜测。不要安装或登录 Claude。

第一次执行仍可能需要你提供订阅归属、允许管理员授权、确认严格防火墙影响及保存浏览器网页。项目地址和节点名不能替代缺失的订阅凭据、管理员权限或客户端安装。**私有仓库需要相应 GitHub 访问权限**，不是公开下载链接。

前置依赖：已安装并正常运行 Clash Verge Rev、Mihomo 服务、Node.js、Python 3.10+ 与 PyYAML。可在审阅后通过 `python -m pip install -r requirements.txt` 安装 Python 依赖。脚本不会自动下载未知软件，也不会替你添加一个不存在的节点。

## 一键入口

根目录只有 **一键网络.cmd**，运行后按菜单选择：

菜单使用黑底亮白文字，状态提示使用亮色，不使用灰色文字。仅打开菜单不会创建备份；首次执行配置时才自动备份。

- **1. 配置**：新电脑询问精确节点名，生成、校验、备份并应用配置；之后执行网络/断网测试。高级用法：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 -Action apply -Node "节点完整名称" -Region SG`。同名节点可加 `-Subscription "订阅名称或UID"`。
- **2. 配置（不改浏览器设置）**：配置网络，跳过浏览器设置和关闭浏览器步骤。
- **3. 恢复**：列出所有快照（按时间倒序），输入编号选择要恢复到哪一份，还原该快照的系统、浏览器及本项目网络设置；保留当前 Clash 订阅、节点更新和选中订阅。
- **4. 保存当前快照**：把电脑当前状态另存为一个新快照，封存校验后提示保存成功；不覆盖已有快照，也不改动任何设置。不必先执行配置即可保存、恢复。
- **5. 补充配置**：安装新软件或新增网卡后，重新扫描当前本地防火墙规则与网卡，禁用非项目出站放行规则、关闭当前启用的网卡 IPv6；入站规则统计后保留。沿用上次配置关联的快照，不覆盖首次备份，不关闭浏览器，不重新选择节点，不运行网络或断网测试。
- **6. 恢复最早状态并重新配置**：先恢复固定首次恢复点并确认联网，再沿用配置记录的精确节点、订阅与出口地区完整配置。执行前必须已有完整配置记录和可校验的原始快照；独立本机看护就绪后才允许改动系统。会关闭 Chrome/Edge，请先保存网页。
- **0. 退出**。

配置、补充配置、恢复和保存快照都需要管理员权限。完整配置和恢复会关闭浏览器，请先保存网页内容；结束后由你自行打开。仅保存快照不会关闭浏览器。重启 Windows 后 IPv6/语言策略才能完整生效。不要移动或删除 `.local`；它被 Git 排除，包含本机恢复所必需的原始记录。

不需要处理浏览器时，给高级命令加 `-SkipBrowser`：配置和恢复均跳过浏览器策略、语言字段及关闭浏览器步骤；WebRTC、语言、指纹相关验证项保持“未测试”，不能声称已全面防护。本项目只处理普通 Chrome/Edge，不配置指纹浏览器。

### 遇到提示时怎么处理

| 情况 | 工具行为与下一步 |
|---|---|
| 缺少 Python / PyYAML / Node.js | 提示缺少的依赖，停止配置；按前置依赖说明处理后重新打开根菜单，不自动安装 |
| 取消管理员授权或操作确认 | 不执行所选操作；需要时重新打开根菜单 |
| 节点不存在、大小写不符或多个订阅包含同名节点 | 在关闭 Clash、写入配置前停止；核对完整节点名，按订阅编号选择或指定唯一 UID，不自动替换节点 |
| 节点或快照编号输入错误 | 提示有效范围，可重新输入；直接回车取消。订阅编号也检查范围，纯数字节点名请用高级参数 `-Node` 指定 |
| 没有快照、清单损坏或机器/用户不匹配 | 停止恢复，保留现有设置；核对本机原始记录，不删除 `.local` 或借用其他电脑的快照 |
| 预检或候选生成失败，尚未写入配置 | 说明停止位置和本地错误记录；处理原因后重试，无需仅为此次失败执行恢复 |
| 已开始写入后失败 | 明确提示可能部分完成；防火墙回滚成功也不代表语言、IPv6 等已恢复，先用菜单 3 恢复关联快照 |
| 防火墙自动回滚失败 | 显示红色提示，公网可能仍被阻断；保留恢复记录，从根菜单重试恢复，详情见 `.local/rollback-error.log` |
| 网络验收失败 | 显示本次失败的检测项目及报告位置，包括 DNS、出口地区、节点故障或核心重启等；不使用上一次操作的成功记录 |
| 保存快照 | 显示采集、保存、封存三步；只有封存校验通过才提示成功，未完整保存的快照不能视为可靠恢复点 |
| 配置或恢复完成 | 说明已完成范围、重启要求与未验证项目；恢复不运行网络验收，缺少 Git/npm 时明确显示未测试 |

完整配置的网络验证会分别提示节点故障、停核和恢复复测阶段；停核期间国内公网也会暂时断开。检测可能需要数分钟，不要仅因暂时没有新输出就关闭窗口。错误与测试记录均只保存在 `.local/`。

每次执行「配置」或「补充配置」都会禁用所有非本项目的本地出站 Allow 规则，包括安装新软件后新增或重新启用的放行规则。只禁用，不删除规则，也不新增应用 Block 规则。新增规则的恢复记录累积保存在关联快照的 `firewall-disabled-by-apply.json`；网卡改动累积保存在 `disabled-by-apply.json`，两者均在改动前落盘，不覆盖首次基线。执行菜单 3「恢复」并选择补充配置完成时显示的关联快照，会一并恢复这些改动。补充失败会尝试撤销本次规则和网卡改动，保留之前配置；失败详情保存在 `.local/last-error.log`。

补充配置要求已有配置记录、完整且属于当前电脑和用户的原始快照，以及现有严格出站策略、四条项目放行规则和一条 SharedAccess 服务阻断规则。缺失时停止，不拿当前配置替换原始备份；旧版四条规则的部署需要重新完整配置。它不会持续监控软件安装，也不会重建缺失的项目规则。入站规则按现有方案保留；本功能不为每个应用新建入站或出站放行规则。其他 VPN、Docker/WSL、浏览器及账号行为仍需在真实环境另行验证。

防火墙恢复清单兼容旧版普通/嵌套数组和 PowerShell 的 `value`/`Count` 包装格式；包装字段、计数或内容异常仍会拒绝。后续写入统一使用普通字符串数组，不覆盖首次快照的封存记录。配置、补充、恢复和防火墙回滚进入系统改动前都会先检查这份清单。如果旧版本因清单格式中断且回滚未完成，不要删除清单或重建基线；更新脚本后重新打开根菜单，先完成待处理回滚，再选择关联快照恢复。语言/IPv6 等部分改动需要完整恢复，不能仅凭防火墙回滚提示视为全部恢复。

## 快照与恢复

统一使用一种快照格式和一套校验/恢复实现；“首次恢复点”和“额外手动快照”只是用途不同。首次恢复点固定记录在 `.local/baseline-selection.json`，不能用当前已配置状态覆盖。旧部署升级时保留原配置关联的快照，且不修改旧快照的内容。完整客户端副本与 `.wfw` 是原始留档；日常恢复按记录逐项撤销项目改动，保留当前订阅和账号等后来数据，不整目录回放旧配置，也不导入整个旧防火墙覆盖后来规则。

- **第一次**执行「配置」时，脚本会在改动前自动保存一份快照到 `.local/snapshots/<时间戳>/`，包含客户端目录、系统设置原值、防火墙导出和哈希清单。
- **之后再执行「配置」不会重复备份**，沿用 .local/baseline-selection.json 固定的首次恢复点；旧部署首次升级时保留已有配置关联的恢复点。没有关联记录时才选择最早自动基线（无自动基线时选择最早手动快照），后续快照不会替换它。
- 想额外留一个还原点，选「4. 保存当前快照」；它按当前状态新建一份，旧快照不动。
- 选「3. 恢复」时按时间倒序列出全部快照，输入编号决定恢复到哪一份；只传 `-Snapshot <目录名>` 可跳过交互。列表用「配置及补充改动关联」标出配置记录所关联的恢复点；不是自动选择最新一份。
- 快照目录名就是本地时间 `YYYYMMDD-HHMMSS`，目录名排序即时间顺序。

备份和恢复均跳过客户端运行锁、缓存及日志，Clash 运行时也能保存快照；配置文件读取失败仍会中止，不会静默漏备份。保存失败的详细错误位于 `.local/snapshot-error.log`。

配置、补充、恢复、保存快照与定时更新共用 `.local/operation.lock`，同一时间只能执行一项；占用时提示稍后重试，异常退出后由 Windows 释放锁。恢复先检查快照完整性、机器/用户及客户端目录，再关闭浏览器和进入还原步骤；检查失败不关闭浏览器，也不重新启动 Clash。

防火墙看护记录绑定本次操作的原始快照；180 秒超时后请求回滚，等待正在执行的防火墙写入步骤结束再处理，避免同时修改。下次操作会先处理尚未完成的回滚，定时更新也会检查该状态。缺少封存的系统备份时拒绝恢复。完整配置会先检查防火墙服务和三个网络配置文件均已启用，再关闭客户端。

恢复 Git、npm、Docker 时只还原代理字段，保留后来新增的其他设置和账号信息；恢复前的当前文件副本保存在 `.local/app-proxy-restore-*/`。手动快照中已有的项目防火墙规则也会保留；新快照登记规则内容，若后来缺失或被改动，恢复会提示未完成。

恢复已配置状态的手动快照时，保留快照原有的项目增强脚本及其当前规则更新，只移除快照后新增的项目脚本和关联；继续保留当前订阅、节点更新及用户后来手动选择的其他脚本。所需项目脚本缺失、被替换，或它指定的精确节点已从当前订阅消失时，恢复预检会停止，不猜测替代节点。重新生成的运行配置必须通过当前节点和分流策略检查，不回放快照中的旧运行 YAML。

首次浏览器语言备份保持不变。之后新增 Chrome/Edge 用户配置时，原语言字段另存到关联快照的 `browser-language-increments/`，每份增量单独登记校验值；恢复时合并读取原备份和已登记增量，不在恢复过程中采集当前状态。校验失败仍会停止，不会用当前设置覆盖或自动“修复”旧备份。

客户端恢复字段写入、清理本项目生成文件或重新加载配置失败时，恢复会报告“部分完成”并返回失败状态，逐项显示未完成项目，详细记录保存在 `.local/client-restore-result.json`。其他文件会继续尝试恢复；解除占用或权限问题后可重试。文件恢复不完整时，不主动向内核加载混合配置。

补充配置会检查防火墙服务、三个配置文件的实际启用状态和默认出站动作，并同时检查持久规则与实际生效规则中的五条项目规则：核心程序及运行路径、TUN 网卡、LAN 地址范围、DHCP 服务与端口、SharedAccess 服务阻断等。规则不符时停止；处理新增规则后再确认实际策略中没有未覆盖的额外出站放行规则，无法完成时尝试撤销本次补充改动。这些配置检查不能替代实际网络测试。

Windows 的 Internet 连接共享可能生成不在普通持久规则列表中的动态放行。完整配置新增一条所有程序、地址、网卡和协议均适用的 `SharedAccess` 服务出站 Block，保留服务本身及其启动方式；普通本机 LAN 直连规则保持原范围。这会限制依赖该服务的连接共享、移动热点及部分虚拟网络路径。只在动态放行的实际程序为系统 `svchost.exe`、服务为 `SharedAccess`、无需认证且不能绕过阻断时，才认定它被这条 Block 覆盖；其他动态规则或组策略仍会阻止配置通过。该判断依据 [Windows 防火墙规则优先级](https://learn.microsoft.com/windows/security/operating-system-security/network-security/windows-firewall/rules)，不构成实际 Docker/WSL 转发测试。完整恢复会移除首次基线中不存在的项目 Block，保留快照原有的项目规则。

LAN 防火墙地址按实际 IPv4 范围核验，兼容 Windows 返回的前缀、点分掩码和起止地址写法；例如 `10.0.0.0/8` 与 `10.0.0.0/255.0.0.0` 等价。范围扩大、缩小、缺失、混入公网地址或无法识别的格式仍会停止配置，不通过放宽规则绕过检查。配置中断后的自动回滚只负责防火墙；先从根菜单执行「3. 恢复」，选择配置记录关联的原始快照，恢复成功后再重新配置。

不要把 `.local` 复制到另一台电脑使用；快照与机器名、Windows 用户 SID、客户端路径绑定，换机器会被拒绝。

### 断网时的独立恢复

菜单 6 在本机启动独立看护进程，确认恢复记录完整且看护已就绪后，再启动恢复和重新配置子进程。它不依赖智能体在线、远程指令或外部下载来触发恢复。恢复阶段最多等待 10 分钟，配置阶段最多 15 分钟；独立看护另有 30 分钟总期限，也会检测主控进程异常退出。子进程的启动标识一并记录，避免误杀复用了相同编号的其他进程。

失败、超时或主控退出时，看护先停止本次工作进程树，再用固定首次恢复点恢复网络。普通恢复失败时仍会尝试串行还原防火墙、启动核心并加载客户端当前生成的配置；不会拿备份中的旧节点 YAML 作为替代。恢复子进程自身也有超时与清理，最终联网探测结果单独记录。恢复期间定时规则更新暂停。

本次阶段、日志与结果保存在 `.local/reconfigure-runs/<编号>/`，正常完成写入 `done.json`，自动恢复写入 `recovery-result.json`。网络恢复后可以继续当前会话并读取这些记录；聊天应用若没有自动重连，需要重新打开此会话。脚本能脱离会话执行，但不能保证运营商断网、系统断电或 Windows 权限/驱动故障时也一定恢复成功。看护失败会保留待处理标记和错误日志，不能将其当作配置成功。

### 所有网卡的 IPv6 配置与恢复

配置和补充配置会枚举全部现有适配器，包括隐藏、虚拟和未连接的网卡，关闭其中启用的 IPv6 绑定，并再次检查是否还有遗漏。没有 IPv6 绑定的适配器无需修改；任何绑定关闭失败都会报告失败。

恢复优先按网卡 GUID 匹配，名称包含星号也不会被当作通配符。首次快照中的网卡恢复各自原始状态；后来新增、且被配置或补充配置关闭的网卡，根据改动前写入的记录恢复。原本关闭的绑定和全局 IPv6 设置保持原值，未记录的后来网卡不擅自启用。已删除的网卡会提示不存在，不会将同名替代网卡误认为原设备。

正常恢复不会修改 Tcpip6 驱动启动方式。如果记录要求启用的绑定仍无法恢复，脚本会报告恢复未完成；应根据具体错误检查系统组件，不能仅凭失败断定组件被移除。内部 `repair-bindings` 属于单独的维护操作，会启用绑定并尝试修复驱动启动方式，不等同于按备份恢复，也不属于日常菜单流程。

## 每一步做什么、有什么用

| 步骤 | 修改及用途 | 影响与边界 |
|---|---|---|
| 环境发现 | 读取实际订阅、增强脚本、生成配置、运行内核路径与控制通道 | 不凭常见路径覆盖陌生客户端；缺少内核或歧义节点就停止 |
| 首次备份 | 保存完整客户端目录、系统各项原值、原防火墙导出和出站允许规则、代理设置、浏览器语言/策略；建立哈希清单 | 含敏感数据，仅保存在 `.local`，不能提交 Git；首次备份不覆盖 |

| 局域网优先 | 保留真实私有地址及原已审核 LAN 规则 | 从 LAN 规则排除 `198.18.0.0/15` fake-IP 地址池，避免误直连 |

| 国内分流 | pluwen 域名名单先转换为 domain；Loyalsoldier cncidr 用 ipcidr，private 用 domain，lancidr 用 ipcidr | 名单不是对全部中国网站的地理证明；不把 private.txt 误当 IP 列表 |
| 海外兜底 | 最后一条 MATCH 指向固定节点组 | 未知海外流量不会因遗漏单条规则回落直连 |
| DNS | fake-ip；默认 Cloudflare/Google DoH 经固定节点，国内名单单独使用国内 DoH；保留本地域名解析 | 沿用“默认海外”的策略，不改成所有域名先询问国内 DNS |
| DNS Type 64/65 | 在每条上游解析路径附加 `disable-qtype-64=true` 和 `disable-qtype-65=true`，覆盖默认/直连/节点域名/系统私有域名策略 | SVCB/HTTPS 查询得到空响应；这不是拦截 64/65 端口。可能失去 ECH 与部分服务发现优化，不关闭 TLS 证书校验，也不等于关闭全部 QUIC |
| TUN | mixed、auto-route、auto-detect-interface、strict-route，接管 TCP/UDP 53 | 接管普通 Windows 程序、curl/git/npm 等；其他 VPN、WSL、容器转发和应用自带加密 DNS需另行实测 |
| IPv6 | Clash/DNS IPv6 关闭；系统 DisabledComponents=255，检查所有现有网卡（含隐藏、虚拟、未连接），关闭启用的 IPv6 绑定，改动前累积写入 `disabled-by-apply.json` | 需要重启；新增网卡后执行补充配置。恢复原始全局值及已记录网卡状态，原本关闭的保持关闭；绑定操作失败会报告未完成 |
| 代理清理 | 关闭系统/WinHTTP 代理，清理 HTTP(S)/ALL/NO_PROXY 及 git/npm/Docker 客户端代理覆盖 | 保存原值。已打开的进程可能保留旧环境变量，需重新启动 |
| 严格防火墙 | 默认出站 Block，禁用原本地出站 Allow，保留核心、TUN、LAN、DHCP 必要路径，并阻断 SharedAccess 服务出站 | 核心程序本身允许出站，必须保持正确配置；SharedAccess 动态放行需核验覆盖条件，未知动态规则、管理员软件及将来新增允许规则仍需审核 |
| 核心故障保护 | 节点坏但核心运行时国内仍直连；整个核心停止时所有公网阻断 | 后一种情况下国内公网也会断。这是有意的严格行为，并非误报 |
| 启动与维护 | 核心服务设为自动启动；国内来源每日 13:00 在当前用户登录期间更新 | Windows 不保证所有开机程序的绝对先后顺序；靠出站阻断保护核心就绪前的流量 |
| 浏览器 | Chrome/Edge WebRTC 限制、关闭浏览器独立 DoH、直接交给 TUN、首选语言 zh-SG/en-SG/zh-CN | 策略可能受个人账号/管理状态影响，需验证实际网页。普通浏览器 Intl 默认 locale 可能仍为 zh-CN，不能伪称已全部变为 zh-SG |
| 区域语言 | Singapore Standard Time、zh-SG、新加坡语言偏好，尽量保留中文 IME | 不删除字体、不安装指纹扩展、不清理登录/Cookie；语言不能改变真实 IP |
| 更新审核 | 规则格式、规模变化、私有地址变更、fake-IP 排除与核心策略做检查；失败保留旧配置 | 第三方 Claude 候选只下载到 `.local` 待审核，不自动合并关键词、ASN 和未知共享域名 |

## 规则顺序

节点连接所需的窄范围例外 / 真实 LAN、私有域名与地址 → 拒绝公网 IPv6 → Claude 进程、官方入站 IP、核心及补充域名 → 国内域名 → 国内 IP 与 GEOIP,CN（no-resolve）→ MATCH 固定海外组。

代理组只能包含指定的实际节点，不能经由另一个可能选 DIRECT 的组。严格模式不是“开启系统代理”；浏览器的 ProxyMode=direct 是交给本机 TUN，不意味着绕过 TUN 直连公网。

“本机访问路由器/NAS 等局域网目标直连”与“允许其他设备使用本机代理”是不同设置；LAN 分流规则不等于开启代理共享。真实私有地址、回环、链路本地、CGNAT/虚拟内网和必要组播仍保留直连。LAN/私有规则审核实际内容，不只看规则集名称：受保护公网域名、全网匹配、未知逻辑规则和未经审核的公网域名会停止候选发布。公共地址、文档地址及过宽保留地址段不再自动当作 LAN；可保留的内网部分会单独展开，改动记录写入 `.local/lan-audit.json`，源订阅不修改。已审核的路由器/本地服务域名继续保留；这不构成所有网页均无法获知国内出口的保证。

额外 `listeners`/`tunnels` 在生成、校验和客户端重新执行增强脚本时都要审核。只接受明确指向固定节点组、绑定本机回环且属于已支持类型的入口；DIRECT、未知出站、替代规则或对外绑定会停止，不静默删除或改写源订阅。默认 HTTP/SOCKS 代理共享设置不在这项审核中，不会被此次代码修复自动改变。

## DNS 64/65 与“所有网卡”的准确含义

过滤设置位于统一的 Mihomo 解析器，作用于进入 TUN/该解析器的流量，不是给每块网卡写不存在的 Windows qtype 防火墙选项。切换以太网/Wi-Fi 时，只要仍被 TUN 接管，相同过滤仍有效。关闭或未连接的网卡无法做联网实测。

**不能按 DNS qtype 检查任意端到端加密 DoH/DoT/DoQ 流量。** 未经解密看不到其中的 DNS 类型。本项目不安装根证书、不做 TLS 中间人解密，也不宣称能过滤未来所有应用自带的加密解析器。浏览器独立 DoH 被关闭，其他加密 DNS应用需要单独审核。

## 备份与恢复的具体含义

新电脑首次配置前自动在 `.local/snapshots/<时间戳>/` 保存快照，包含机器和用户绑定以及校验清单；后续配置复用已固定的首次恢复点；已有配置的关联恢复点会保留，不随新增快照改变，不重复备份。手动保存的快照按当前状态新增，不覆盖旧快照。恢复只还原本项目记录过的项目，不是 Windows 出厂重置，也无法还原从未记录的历史人为操作。恢复浏览器只恢复对应语言字段/策略，不拿旧浏览器整个目录覆盖当前数据。

客户端源订阅原文件不修改。配置时新增独立的项目增强脚本，组合原自定义脚本后关联到所选订阅，不覆盖原脚本文件。订阅原脚本关联的恢复记录累积保存在关联快照的 `client-changes.json`，先记录再改动；旧版本已覆盖的脚本，恢复时只移除可识别的项目代码。

恢复不再整目录回放旧客户端文件：保留当前订阅列表、订阅地址、排序、更新信息、当前选中订阅，以及新增/更新的节点和源文件；不重新添加后来主动删除的订阅。只撤销项目脚本及关联、还原项目改动过的客户端网络字段，保留其他后续设置。首次完整备份仍留作原始记录，不被当前状态覆盖。

恢复订阅文件后会等待旧进程退出，优先使用观察到的实际程序路径启动 Clash，避免计划任务仍处于运行状态时忽略新的启动请求。随后等待它使用当前订阅生成运行配置；不会把备份中的旧节点运行配置重新加载到内核。未能启动客户端、源文件有误或 90 秒内无法确认生成完成时报告“恢复未完成”，保留详细记录供重试。自定义脚本会影响运行配置时仍需在实际客户端核验，此处不保证所有非标准增强方式都能自动确认。

防火墙完整导出用于留档；主恢复路径按已记录的配置文件默认动作及原允许规则逐项恢复。本机此前完整 .wfw 导入曾失败，所以不把“能导出”当成“导入已验证”。

## 验证与成功标准

`scripts/verify.py` 自动检查以下项目。完整配置将节点故障、核心退出和恢复复测分别保存在 `.local/verification-runs/<本次编号>/`，`.local/verification.json` 汇总同一次操作的各阶段；后续复测不会覆盖之前的断网证据，也不混入上次操作的成功记录。

- 百度返回 200，淘宝返回 200/301/302；`ipinfo.io` 的出口国家必须等于 `-Region`。逐连接是否为 DIRECT 仍需观察实际连接记录。
- 自动验收不向 Claude/Anthropic 发起 HTTP 请求，不打开或登录 Claude；Claude HTTP 可达性、账号和应用可用性均保持未测试。节点中断测试使用 `ipinfo.io` 等其他海外检测目标。
- 向 `8.8.8.8:53` 发 TCP/UDP 的 A、64、65 查询：A 必须有结果，64/65 必须为空；并确认 `claude.ai` 得到 `198.18.0.0/16` 的 fake-IP，证明解析确实进入 TUN，而不是直连外部解析器。
- 原生 UDP STUN 返回映射地址；清空代理环境变量后 `git ls-remote`、`npm ping` 可用。
- IPv6 公网地址不可达。
- 模拟选定节点失败：海外请求失败、国内仍可访问，`finally` 中恢复节点并复测出口。
- 停止核心：国内外公网都不可连接，重启后恢复。`verify_core_exit.py` 记录 `domestic_also_blocked`，明确这是全阻断模式，不是“国内仍可用”。

STUN 请求使用标准 magic cookie，并检查响应来源、事务编号、长度和有效公网映射。STUN 或已安装的 Git/npm 检查失败时，整体验证失败；缺少 Git/npm 时单独记录“未测试”和原因，不能当作该项通过。停核测试即使重启失败也会保存失败阶段记录。

Git/npm 检测每次最多等待 20 秒，失败最多尝试两次，逐次记录结果。Git 检测禁用交互式凭据请求；超时会清理本次检测启动的进程树，避免 Windows 下联网子进程占用输出管道、导致超时后仍长期卡住。无法确认进程树已清理时停止重试，持续失败仍使配置失败。根菜单会显示本次 Git/npm/STUN 的具体失败项，不混入旧操作记录。

候选校验拒绝 direct/global 模式；验收先读取核心实际 mode，非 rule 时停止联网探测。UDP 验收在 STUN 套接字仍打开时读取连接元数据，按本地端口、目的地址/域名和端口定位唯一 UDP 连接，要求代理链同时包含指定节点和固定组且不含 DIRECT。再核对映射地址的地区；TCP/UDP 地址不同会分别记录，地区或代理链无法确认时验收失败，不把“能收到 UDP 响应”当作防泄露通过。出口地区查询依赖 ipinfo 的结果，不证明账号资格；实际浏览器 WebRTC 仍需独立验证。

完整配置在关闭应用前检查浏览器已有策略，包括用户/机器级 `ProxySettings`、网址级 `WebRtcIPHandlingUrl` 和 Chrome 机器级 `ForcedLanguages`。发现冲突时停止，保留原策略；应用阶段再次检查。`-SkipBrowser` 跳过此预检和浏览器改动。策略写入结果始终标明实际浏览器行为未验证；Edge 登录个人 Microsoft 账号的配置文件可能忽略 WebRTC 和首选语言策略，仍需逐配置文件实测。

以下项目脚本不代测，必须人工完成或标记为未验证：

- 实际连接元数据里的每一条代理链（脚本只核对固定组与出口国家）。
- 浏览器 WebRTC、语言、时区、指纹：在真实配置文件里用 browserleaks.com/webrtc、browserleaks.com/javascript、CreepJS 查看。
- Docker/WSL/Tailscale 及其他虚拟网卡：必须在各自运行环境内测出口，宿主机 curl 不能代替。
- 任意应用自带的加密 DNS（DoH/DoT/DoQ）：未解密看不到 qtype，不在过滤证明范围内。
- `python scripts/test_dns_filter.py` 是隔离正样本实验，用于排除“域名本来没有 64/65 记录”的假阳性，不修改运行配置。

脚本记录“通过/失败/未测试”，不把未知状态写成成功。断网测试会短暂中断正在使用代理的连接。新的 Windows 适配器做过本机候选生成、Mihomo 校验和离线回归，但没有在另一台全新 Windows 上完成完整往返，初次部署仍须按清单验收。
